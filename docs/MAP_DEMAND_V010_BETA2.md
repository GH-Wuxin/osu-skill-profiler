# 0.10.0-beta.2 · 容错与节奏修正版

状态：**启发式公开试用版**。beta.1 模型文件保持不变，继续保留显式回滚路径。
本轮只改 Stamina、Micro Precision（内部键 `spatial_precision`）、Finger Control。
Aim Control、Jump Aim、Flow Aim、Raw Speed、Reading、Endurance 的数值及证据保持 beta.1 原样。
因此这不是九维全面重标定；后三者中的耐力也没有和 Endurance 混合。

## 边界

- 三个新维度不以总 SR 作底数、乘数或保底值；其他六维沿用 beta.1，不能宣称整个模型已与 SR 脱钩。
- 只使用经过 Mod 变换的真实 note 时间、目标半径和局部排列；不根据 mapper 写的 BPM/分拍给排列定性。
- 不读取人工目标分，不按 BID 特判。人工案例用于寻找缺失机制，不作为拟合标杆。
- 共用原始事实，不读取另一维的最终分数。诊断保留每个修正维度的计算证据。
- 新 `algorithm_id`、`calibration_id`、版本号隔离旧缓存。CLI、运行时注册表和 HTTP 工作台均支持 `v010-beta2`；旧版本可以显式选择。

## Stamina：同一段内绑定速度与长度

旧问题：全图高分位击打速度，与一个宽松 180ms 阈值找出的最长链拼接；半速恢复和滑条头也给高速度链贡献长度。在 14 次/秒附近速度门饱和，7 连就可能接近满分。

新规则：

1. 在 6～40 次/秒的多档节奏阈值下各自寻找连续击打段。低于本档速度的间隔切断本档；它仍可支持更慢的一档。
2. 7 note 开始提供正证据，但入口平滑，7 连不会当作长串。
3. 每段的实际速率 `r = 间隔数 / 实际秒数`，不借用全图 P90；实际时长不用旧 strain 的最小 dt 地板。
4. 速率压力 `((r - 4) / 8)^1.65`（负值归零）；持续因子同时考虑 note 数和真实秒数，均为渐近增长。
5. 同档有效段的累计时长只给有限的重复支持（0.8～1），不能让短快段借用别处的慢长串。
6. 最终 `10 × (1 - exp(-1.2 × 局部负荷))`，保留 Stamina 的 0～10 语义；取证据最强的实际段。

纯合成同速串的示例（不是玩家体力实测）：

| 场景 | 候选 Stamina |
| --- | ---: |
| 210 BPM 四分，7 note | 0.83 |
| 210 BPM 四分，25 note | 4.54 |
| 180 BPM 四分，200 note | 6.30 |
| 210 BPM 四分，200 note | 7.57 |
| 240 BPM 四分，200 note | 8.48 |

这里 BPM 只是解释合成间隔的语言，代码输入仍是毫秒。速率压力超线性增长，最终有界评分会逐渐饱和，不应把 0～10 输出本身理解成指数体力单位。

## Micro Precision：目标容错为主体

参考 ppy 的目标半径和距离归一化思路，而不是把整个 Aim 复制成 Precision。

- 半径沿用提取器，等价于 `r = (54.4 - 4.48 × CS) × 1.00041`。
- 以 CS4 半径为参照，目标压力采用 `(r_CS4 / r)^1.65`，再乘一个小圈附加因子的平方根。指数与评分系数是本项目的实验选择，**不是 ppy 的独立 Precision 公式**。
- 因此低 CS 有实际减法，高 CS 连续上升，不在 CS8 附近封顶。
- 位移和速度只提供有上限的执行上下文：位移从 100px 增到 400px 不会让该维变成另一个 Jump Aim。完全没有重定位时不凭小圈空加分。
- 微修正的几何检测改用固定物理距离，不随目标缩小而突然失去证据；这修复了同一排列提高 CS 反而降分的问题。
- 聚合使用局部最高八个事件均值的峰值（90%）加全图中位数（10%），避免少数难段被全图零值 P90 吞掉。

固定排列、速度下，CS0～10 严格递增，并验证 CS8→9→10 不出现旧平台。固定测试几何中，CS7 的慢速重定位也可以高于 CS3 的快速重定位。

上游参考固定在 [ppy/osu 48c4800](https://github.com/ppy/osu/tree/48c4800e3ae4ee752452cdff83bd3787ccf3105f)，主要查看：

- `osu.Game/Rulesets/Objects/Legacy/LegacyRulesetExtensions.cs` 的 CS scale；
- `osu.Game.Rulesets.Osu/Difficulty/Preprocessing/OsuDifficultyHitObject.cs` 的半径归一化与 SmallCircleBonus；
- Snap/Flow/Agility Aim 各自使用小圈证据的方式。

这些是机制参考，不把半径缩放比例冒充 SR 倍率。

## Finger Control：击打组、启停和节奏重建

旧问题：主要对相邻间隔做比值统计，250ms 以外直接忽略，3:2 等比例又被常见比例表抹掉；还会被全图 P90 稀释。因此既可能漏掉复杂变速，又不区分同一模式的实际执行速度。

新规则：

- 先将真实击打间隔分成局部稳定节奏组（允许约 5.7% 时间误差），保留组长、起止、滑条持键上下文。
- 在节奏组切换处计算执行速度、变化幅度、前后组建立程度、快组长度变化、奇偶变化，以及恢复时间。奇偶只是潜在交替击打需求，**不是推断玩家实际用了哪根手指**。
- 恢复是连续衰减，不存在 249ms 有分、251ms 直接消失的断崖。
- 重复的完整“节奏＋组长”模式有可预测性折扣。
- 同时检测是否只是沿用同一局部 pulse、期间省略了一些拍：pulse 必须实际出现，并获附近多组支持，不能凭空求出一个极小公约数。它只提供有限折扣，不把同网格的组长变化全部清零。
- 不再使用“某比例天然简单/罕见”的白名单。3:2 是否可预测由局部证据决定。
- 在实际 6 秒窗口内聚合转换负荷，保留困难小段；低幅度基础击打分单独封顶 1.5。没有复杂切换的高速匀速串不会因此得到很高的 Finger Control。
- 超过 1.5 秒的间隔作为乐句分隔，不作为一组极慢节奏制造虚假切换；spinner 不提供击打 note。

开发中首轮曾把普通停顿抬成节奏重建，120 组本地案例的 Finger 均值从 3.72 升到 6.12。增加有证据的局部 pulse 可预测性后，同一批候选均值为 4.29、中位数为 4.29（原中位数 4.31）。这只是排查广泛偏移的对照，不把追平旧均值当成目标。

## 验证和复跑

单元/机制测试：`tests/test_map_demand_v010_beta2.py`。
覆盖局部速率和长度不串用、7 连入口、真实时钟、spinner、恢复、CS 单调性、微修正证据不丢失、节奏速度变化、固定 pulse、重复模式、难段不被填充稀释、输入不变、三维修正不读 SR、其余六维完全不变，以及运行时 beta.2 选择和 beta.1 回滚。发布测试另覆盖 HTTP 工作台的 NM/HD/HDDT 分析、缓存身份区分和带版本、Mod 的反馈保存。

离线单图：

```powershell
python tools/map_demand_v01/cli.py analyze --map '<本地 .osu>' --mods HD DT --algorithm v010-beta2 --out tmp/beta2-example.json
```

批量对照：

```powershell
python tools/evaluate-map-demand-beta2.py --cache-root '<本地分析缓存>' --limit 100 --out tmp/beta2-evaluation.json
```

可加 `--manifest`、`--songs-root`、`--osu-db` 三个参数，补上旧典型案例及每个 1～2、2～3、3～4 星档最多三张本地图。
`--extra-map BID PATH NM_STARS` 可重复；这个 SR 只用于旧模型和未改的六维，不进入新三维公式。
脚本不发网络请求、不操作进程，只写指定的报告。对照样本是本地便利样本，不是玩家群体的无偏抽样。

## 仍需玩家验证

独立尺度不等于已有绝对正确的标尺。Stamina 的分档阈值、局部节奏组/可预测性、Precision 的 CS 非线性仍是启发式；极高 CS 的无上限输出尤其需要更多案例。复杂滑条持键和玩家具体指法尚未完整模拟。正确识别同节拍省略和真正节奏转换仍可能存在边界误差。

## 试用切换与回退

