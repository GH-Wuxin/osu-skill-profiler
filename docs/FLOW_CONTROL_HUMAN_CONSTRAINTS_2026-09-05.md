# Flow / Aim Control：玩家约束与建模假设

仅用于这两轴。玩家陈述、工程假设、实验观察分开记录；不能用公式解释来替代体感验证。

## 玩家已经确认

1. Flow 执行难度随连续维持长度显著上升，不能在证据充分之后停止增长。
2. 间距和连续维持时长共同增强难度。其他条件相近时，长且大间距的 Flow 应明显难于短而大间距、长而小间距。用户说“类似相乘”是关系描述，不是指定公式。
3. 短滑条会缓解部分持续负担，但负担仍明显延续。它不是把此前负荷完全清零的边界；具体缓解速率尚未给出。
4. Affection HDHR 的 Flow 明显难于 Tower [Acme] HDHR。Tower 只是原 BP 前十里相对最接近的，不是同档参照。区别主要来自转弯、分离和瞄准控制协同，不能只用间距/BPM 解释。
5. 分离：节奏串时间上连续，空间上分组隔断。中间有滑条则不属于此处讨论的瞬时分离机制。这与第 3 条的持续负荷恢复是两件事。
6. Flow 强本来就可能需要很高 Aim Control。两轴不互斥，没有固定分数池；不能为了降低相关性排除普通 Flow 的真实控制需求。
7. Aim Control 主值的目标是“有足够证据成立的最难局部的控制需求”。
8. 4007768，Rumble [Jungle]，NM：经典、几乎纯 Aim Control，玩家参考约 7.5。
9. 2809623，true DJ MAG top ranker's song Zenpen (katagiri Remix) [KEMOMIMI EDM SQUAD]，NM：世界级 Tech，Aim Control 要求极高，玩家参考约 8.2。
10. 用户还指出，Aim Control 超过这两张参照、而谱面星数低于它们的图“几乎没有”。这是相对地位的提示，不是把官方总 SR 写成 Control 上限，也不是所有 BP 的逐图标签。
11. 查看背景确认谱面后，用户指出 I [Phantasm]（4410462，此次比较为 HD）属于跳串综合，Aim Control 最多约 5.8，不能更高。因此同时限候选的 7.7325 仍明显失败，不能以比旧值 9.3245 低为理由接受。

12. Jungle 的控制来源包括圆圈和滑条/衔接；用户随后明确更主要是 circle。这不等于确认算法选出的 55.747–56.711 秒就是全谱真正最难处。
13. True DJ 则是圆圈与滑条/衔接都有，难分主次。不能把 Jungle 的“圆圈为主”推广到 True DJ，也不能只验证纯圆圈赢家便宣称已覆盖其完整控制需求。
14. 用户看过排列示意后明确：默认 I 片段（259.206–260.124 秒）“完全就是跳切”，不认可用它作为高 Aim Control 的证据。该局部标签不等于 I 全图 Control 为零，也不是所有跳切一律零控制的规则。
15. 同一示意中的 Jungle（55.747–56.711 秒）和 True DJ（103.743–104.537 秒）两个圆圈片段，用户明确都是“非常标准的分离”。这是局部谱型标签，不是这两个局部各自应为 7.5 / 8.2 的数值标签，也未确认它们为全图最难处。
16. 算法主动筛出的三个案例被用户确认全部严重虚高：4572837 Necrofantasia ~ Remix [Youkai of Boundaries] HD（当前 8.9221）、845391 Tower Of Heaven [Heaven] HDHR（当前 8.5275，注意不是 Acme）、657916 Blue Zenith [RLC's Extra] HDHR（当前 8.3723）。
17. Tower [Heaven] HDHR 的用户体感参考为 6.4–6.7。Blue Zenith 只有严重虚高的定性标签，不能自行补写精确目标。
18. 用户已 FC 上述 Necrofantasia，并补充其 Aim Control“顶破天也就 5 星出头”。这是大致上限，不能伪造为精确 5.1 / 5.3，FC 本身也不是低控制难度的独立证明。
19. 用户随后补充 Blue Zenith [RLC's Extra] HDHR 以纯串为主，Aim Control 约 5.8–6.5。此范围取代第 17 条中“尚无精确数值标签”的历史状态；它并非零控制或所有串图统一封顶的规则。此前离线候选曾为 6.6095，不能为了跨过边界专门消掉这 0.11。
20. 用户解释绝对时间的体感差别：以 180 ms 与 100 ms 为例，前者可以像打跳一样移过去，后者需要精确控制移动距离才能快速完成转换。两值是比较示例，不是通用反应时间或精确分类阈值。是否获得调整余裕不能仅凭跨组/串内间隔的倍数判断；实际间距、目标大小和前后移动仍需同时考虑（后三项为建模待检验因素，不是用户新给的定量函数）。
21. 用户补充：极高难度谱面的伴随 Aim Control 需求本来就该升高；但当 Control 不是主要难点时，不应被模型抬得比该谱真正的主要难度更高而丢失主次。所有技能轴都需覆盖低、中、高难度，不能只围绕当前几个高难度参照局部调节。本轮实施范围仍优先 Flow / Aim Control。
22. 用户明确主次：Blue Zenith HDHR 以耐力为首要难点，兼有速度、约 6–7 的 Flow 和一些跳切，Control 仍按此前约 5.8–6.5。这两个范围重叠，不可推导为严格的 Flow 明显高于 Control。Affection HDHR 则明确 Flow 高于 Aim Control，同时 Control 不会很低；尚无其 Control 的数值下限。
23. 用户明确：固定排列、间距和 BPM，仅提高 CS，对 Aim Control 的影响“极大”。不能把这项要求完全归到 Spatial Precision 而让 Control 保持不变；用户未指定指数或精确增幅。
24. 用户看过本轮原谱几何/时序回放后确认：Affection HDHR 的 150.240–156.410 秒能代表所述多转向/分离难点，Blue Zenith HDHR 的 128.835–136.560 秒能代表其 Flow 部分。这是片段代表性标签，不是逐物件分类、局部星数或全谱最高分窗口认证。回放已应用 HR 几何和真实圆圈半径，但未模拟 HD 显隐、堆叠、音频或玩家光标。
25. 用户明确 Altar NM（1451703）的 38.367–40.186 秒是“距离越来越大的四方跳”。整段作为 Flow 误收反例；不能把最小的四方单独当成 Flow 正例，也不扩写成全图 Flow 数值标签。此前的开头录像未覆盖这个候选高分局部，不能替代本次局部确认。
26. 仅比较 Aim Control，用户个人倾向 Jungle NM 高于 Affection HDHR，同时强调两者都挺高，自己“打不明白 Jungle”。这是带保留的个人排序，不是明确差距或 Affection 的数值上限；不能由未能打明白推导星数差，也不能把当前 Affection Control 8.12 当作已验证的 Flow 下限。
27. 用户随后强调：Jungle / Affection 仅是两个案例，目标是避免明显偏差，不要求严格拟合，需防止过拟合。第 26 条只作定性审查线索；不能为了满足它继续局部调整参数、发明误差容许区间或把近似 7.5 变成精确目标。已暴露案例的残差改善须与机制检查和跨难度稳定性分开报告。

第 21 条的工程解释与限制：需要同时验证同轴跨谱面的绝对需求排序、同谱跨轴主次及跨难度段的增长，不能仅因某个候选降低误判谱就接受。它不自动授权把官方总 SR 当作单轴上限、将伴随轴强行截断为主轴固定比例，或预先为每张谱指定唯一主轴；共同主项仍可能存在。主次标签须来自玩家判断或已验证证据，不能由当前算法排名循环定义。现有几个已标注样本尚不足以验证低、中、极高各段的增长曲线。

误判候选由模型从已暴露的开发语料主动筛选，用户判断熟悉的谱即可。不能要求用户预知算法的误判，也不能把自动筛查的未标注案例记为低 Control。

这些数值参照均为开发反馈，不能当作独立测试集。Control v0.2 的机制选择与共享换算参数已经参考这些反馈进行人工开发取舍，没有自动搜索或逐谱修正；不能继续声称参数选择完全独立于这些标签，也不能报告独立准确率。

## 工程方提出、尚待验证的假设

玩家的暂定解释（原话含“可能”，不是确认的因果标签）：I 的大跳接小串间隔给足了反应时间和调整时间。该假设需要通过固定排列改变转换间隔的对照验证，不能直接把节奏变化设为普遍的 Control 降分条件。

- 将纯点击节奏变化与额外空间控制分开：同一直线、同一匀速轨迹，仅按比例改变落点间距和击打间隔，不额外产生空间速度调整。这不否认 Reading / Rhythm 要求。
- 将间距转换到同一个移动时限后比较，保留实际速度变化、方向变化和时限压力。
- Flow 累积执行负荷原型使用局部强度平方的时间积分再开方；1 秒为单位参照。这只是候选，不是玩家给出的函数，也不是生理定律。
- 原型的方向门槛、分离连接条件、短滑条指数恢复速率均未得到人类定量验证。通过人工排列的单调性测试，不代表真实谱面有效。

## 必须保留的失败判据

- Flow 候选若颠倒 Affection / Tower 已确认顺序，就不能因为长串数值升高而采用。
- Aim Control 不得只用一个全轴倍率同时压低普通串图和真正控制谱。
- 不能把 Altar 等历史对照说成当前已发生的 Jump→Flow 误收；它们用于防止新方案重新引入回归。
- 两张数值参照、BP100、Affection/Tower/Lunatic/Altar 都已暴露于开发。数量不等于独立标签数量。
- 未覆盖的滑条方向仍是未知，不能补成零、完整覆盖或假想玩家轨迹。
